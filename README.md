# E3272s‑153 USBL — полная реконструкция загрузчика (исходники + сборка)

Пакет содержит **всё**, что нужно разработчику для работы с загрузчиком (USBL, burn‑режим)
USB‑модема **Huawei E3272s‑153**: читаемые исходники на C, ассемблерный исходник, из которого
загрузчик **собирается обратно байт‑в‑байт**, полную документацию, дампы и инструменты.

**Устройство:** Huawei E3272s‑153 (Мегафон М100‑3 / Билайн E3272), платформа Balong V7R1,
чип HiSilicon HI6920, ARM Cortex‑A9, ОС VxWorks 6.8 (сборка 17.05.2013), прошивка
21.431.99.07.00. Итоговый бинарник — 1 754 444 байта.

## ✅ Проверенная сборка обратно

Из исходника `rebuild/` (header.s + stub.s + body.s) образ собирается командой:

```
python rebuild/make_rebuild.py build
```

и результат **побайтно идентичен оригиналу**:

```
SHA-256  8e0939823f26ca09ba95335df32a8d830c8898b0a1b566c9d153237a8f346805
Размер   1 754 444 байта   (header 84 + stub 876 + body 1 753 484)
Статус   MATCH, 0 ошибок ассемблера (проверено 2026-10-19)
```

Механика гарантии: каждая 4‑байтная позиция кода либо ассемблируется в **ровно те же байты**
(Keystone, проверка на месте), либо выводится директивой `.word` — поэтому совпадение не
вероятностное, а гарантированное по построению; финальный SHA‑256 подтверждает.

## Быстрый старт

**1. Найти функцию:**
```powershell
Select-String "BSP_SetLogLevel" source_c\index\ALL_FUNCTIONS.tsv   # → VA, модуль, файл
```
далее — файл в `source_c/src/<модуль>/…`, в заголовке функции — адрес, вызовы, строки.

**2. Собрать образ:**
```powershell
python rebuild\make_rebuild.py build     # → rebuild\out\usblsafe-327x.bin, SHA-256 совпадёт
```

**3. Пропатчить и собрать:**
открыть `rebuild/body.s`, найти адрес (VA) по `source_c/index/ALL_FUNCTIONS.tsv`,
править (директивы `.word`/`.byte` для данных, инструкции — как есть), затем снова
`make_rebuild.py build`. Размер образа менять нельзя (заголовок фиксирован bootrom‑ом,
см. `docs/10_MODIFICATION_GUIDE.md` §2.3). Все проверки целостности и ловушки — там же
(главная: слово 0x2ffffffc должно равняться **0x98765432**, иначе `nand_erase_all()`).

## Ключевые факты (шпаргалка)

```
Карта адресов : VA = file_off − 0x3C0 + 0x30004000;  стаб: file 0x54-0x3BF @ IRAM 0x2FFE4000
Тело          : код 0x30004000-0x3012E06B (3889 именованных функций), данные до 0x301B018C
Консоль       : UART 0x90007000 (PL011), 115200 8N1, клок 48 МГц, IRQ 102 — stdin/stdout VxWorks
USB (burn)    : DWC HS, VID 0x12D1, PID 0x1C05, профиль MDM+PCUI+DIAG
Прерывания    : GIC, 160 линий; SD 108, PMU 127, WDT 84, GPIO 112–117, UART 102
NAND          : 256 МБ; ptable @0x1E000; kernel @0x3300000 (3 МБ); VxWorks @0x6A0000 (32 МБ)
RAM           : 128 МБ (в USBL-ядре видно ~24.7 МБ: sysMemTop 0x301C4C30); без FPU (soft-float)
Бэнды -153    : маски 0x00960081/0x000800C4 → B3/B7/B8/B20 (+B1 рантайм, см. docs/08 §4)
Опасность     : слово @0x2ffffffc ≠ 0x98765432 → nand_erase_all() — полное стирание NAND
```

## Как это было получено (воспроизводимость)

1. Таблица символов VxWorks извлечена сигнатурно из образа (3983 имён) — `tools/scratch_symtab*.py`,
   `tools/scratch_extract_syms.py` → `artifacts/symbols.csv`.
2. Линейный дизасемблер (capstone) — `tools/scratch_disasm.py` → `artifacts/disasm_full.asm`.
3. Ghidra 11.3.2 headless (импорт @0x30004000 + символы + анализ + декомпил всех функций) —
   `tools/ghidra_scripts/`, `tools/scratch_run_ghidra.ps1` → `artifacts/decompiled_all.c`.
4. Нарезка на модульное дерево + индексы — `tools/gen_tree.py` → `source_c/`.
5. Ассемблерный исходник с побайтовой верификацией — `tools/make_rebuild.py gen` → `rebuild/`.
6. Майнеры фактов (ptable, характеристики, бэнды) — `tools/mine_*.py`.

## Ограничения и правовые замечания

- `source_c/` — результат декомпиляции (Ghidra): `undefined4`/`DAT_xxx`/`FUN_xxxxxxxx` —
  автотипы/автоимена; это **справочный код**, а не собираемый проект (сборка — через
  `rebuild/`). Расшифровка обозначений — `docs/DEVELOPMENT.md` §2.
- Часть периферийных регистров Balong остаётся без имён (заводских заголовков не существует);
  реконструированные карты — `docs/02`, факты — `docs/08`.
- Прошивка принадлежит Huawei. Пакет предназначен для исследования собственного устройства,
  совместимости и порта Linux; распространение проприетарных фрагментов — на вашей ответственности.
- Не прошивайте раздел `BootLoad` без подтверждённого bootrom‑канала восстановления
  (тестпоинт): A/B‑резерва у него нет (docs/11 §3.2).
