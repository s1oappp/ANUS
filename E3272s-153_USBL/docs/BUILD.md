# BUILD.md — сборка образа обратно из исходника (проверено байт‑в‑байт)

## 1. Из чего состоит образ

| Часть | Файл | Смещение в образе | VA исполнения | Размер |
|---|---|---|---|---|
| Заголовок (для bootrom) | `rebuild/header.s` | 0x000 | — | 84 (0x54) |
| Стаб первого уровня | `rebuild/stub.s` | 0x054 | **0x2FFE4000** (IRAM) | 876 (0x36C) |
| Тело VxWorks 6.8 | `rebuild/body.s` | 0x3C0 | **0x30004000** (SDRAM) | 1 753 484 (0x1AC18C) |

Итог: `rebuild/out/usblsafe-327x.bin` = header + stub + body;
SHA‑256 оригинала: `8e0939823f26ca09ba95335df32a8d830c8898b0a1b566c9d153237a8f346805`
(эталон в `rebuild/expected.sha256`).

## 2. Авторитетный путь сборки (Python + Keystone, ничего больше не нужно)

```powershell
python rebuild\make_rebuild.py build
```

Ожидаемый вывод:

```
header.s: OK (84 байт)
stub.s: OK (876 байт)
body.s: OK (1753484 байт)
rebuilt : 1754444 8e0939823f26ca09ba95335df32a8d830c8898b0a1b566c9d153237a8f346805
original: 1754444 8e0939823f26ca09ba95335df32a8d830c8898b0a1b566c9d153237a8f346805
MATCH | errors: 0
```

Требования: Python 3, `pip install capstone keystone-engine` (capstone нужен только для
перегенерации исходника, для сборки достаточно keystone).

### Почему сборка точна по построению

Генератор (`make_rebuild.py gen`) для каждого 4‑байтного слова кода:

1. дизассемблирует его (capstone) и пробует ассемблировать текст обратно (**keystone**);
2. **сравнивает полученные байты с оригиналом**; при совпадении пишет инструкцию;
3. если не совпало (литеральные пулы, данные внутри кода, экзотические кодировки) —
   пишет `.word 0x............`.

Сборщик просто повторяет шаг 1 для строк‑инструкций и копирует байты для `.word/.byte/.asciz`.
Поэтому любая строка либо доказанно кодируется в исходные байты, либо заменена на точные
данные — расхождение возможно только при ошибке парсера, и оно ловится финальным SHA‑256.

## 3. GNU‑toolchain путь (экспериментальный)

`rebuild/Makefile` и `rebuild/build_gnu.ps1` собирают те же `.s` через `arm-none-eabi-as`
+ `objcopy -O binary`. Синтаксис файлов GNU‑совместим (проверялся на Keystone; отдельные
директивы `.asciz`/`.byte` идентичны). **Этот путь не верифицирован** в данной среде
(тулчейн не устанавливался): после сборки обязательно сверьте SHA‑256 с `expected.sha256`.
Если GNU‑as отвергнет строку — это косметика конкретной инструкции: замените её на
`.word` (байты не изменятся).

## 4. Рабочий цикл патча

1. Найдите функцию: `source_c/index/ALL_FUNCTIONS.tsv` → VA → `source_c/src/<модуль>/*.c`
   (тело, вызовы, строки).
2. Найдите её в `rebuild/body.s` по баннеру `; =============== ИМЯ @ 0x3XXXXXXX ===============`
   или по адресу в комментарии `@ 3XXXXXXX`.
3. Правьте **только содержимое**: строки‑инструкции и директивы данных. Длину образа
   менять нельзя — заголовок (`header.s`) фиксирован контрактом bootrom (entry стаба +0x2C,
   размер тела +0x38, адрес загрузки +0x3C, смещение тела +0x40; см. docs/00 §3).
   Хотите больше кода — только за счёт свободного места внутри тела (нули в конце).
4. `python rebuild\make_rebuild.py build` → убедитесь, что `MATCH` сменился на ваш
   ожидаемый размер, а сборка прошла без `ERR`.
5. Проверка целостности при прошивке: путь TF/FS требует корректных юнит‑CRC и
   `TFUP_ValidateCRCWithLic`; USB‑DLOAD — корректных HDLC‑кадров (CRC‑16 PPP‑FCS).
   Все барьеры и риски — `docs/10_MODIFICATION_GUIDE.md`.
6. **Перед прошивкой**: полный дамп NAND, подтверждённый bootrom‑канал (тестпоинт),
   помнить про `nand_erase_all` при слове 0x2ffffffc ≠ 0x98765432.

## 5. Перегенерация исходника с нуля

Если нужно пересоздать `.s` (например, после правки `artifacts/usblsafe-327x.bin`):

```powershell
cd tools
python make_rebuild.py gen        # читает ../artifacts/usblsafe-327x.bin? нет —
                                  # в tools/ путь к оригиналу задан на ../artifacts
```

Скрипт в `tools/` — рабочая копия генератора (пути: `../artifacts/usblsafe-327x.bin`,
`symbols.csv` там же). Он создаст `header.s/stub.s/body.s` рядом с собой; скопируйте их в
`rebuild/` и пересоберите. Полный цикл воспроизведения всего пакета: см. `docs/DEVELOPMENT.md` §4.

## 6. Как читать .s

- `; ===== ИМЯ @ 0xVA =====` — баннер функции (имена из таблицы символов).
- `@ 30004000` в конце строки — адрес инструкции/слова.
- `.word 0x........` — данные/литеральный пул или невоспроизводимая кодировка (байты точные).
- `.byte 0x..,...` — сырые байты (заголовок, непечатные данные).
- `.asciz "..."` — C‑строка с завершающим NUL (читаемо и точно).
- Переходы аннотированы `; -> ИМЯ` (по таблице символов).
