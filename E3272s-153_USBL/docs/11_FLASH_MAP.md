# 11. Карта флеша E3272s‑153: дефолтная ptable расшифрована + новые факты

> Источник: указатель `DAT_3002c454` → дефолтная RAM‑таблица разделов @VA **0x3018000C**
> (эта таблица пишется во flash @0x1E000 при финализации DLOAD — docs/06).
> Чтение сырых слов из `usbl_payload_30004000.bin`; [гип] — интерпретация поля.

## 1. Формат записи (уточнён по дампу, 0x30 байт)

| Смещение | Поле | Пример (BootLoad) |
|---|---|---|
| +0x00 | имя, ASCII[16], NUL‑pad | `BootLoad` |
| +0x10 | offset во flash | 0x00000000 |
| +0x14 | ? (0) | 0 |
| +0x18 | size | 0x00020000 |
| +0x1C | load_addr (VA) | **0x2FFC0000** |
| +0x20 | addr2 / exec | 0x2FFC0000 |
| +0x24 | **type** (код поколения R1) | 0x00000101 |
| +0x28 | flags (bit3 — validity активной копии) | 0x00000000 |
| +0x2C | seq (счётчик поколений A/B) | 0 |

Конец таблицы — маркеры `T` (type 0x200, flags 0x1, @0x3018033C) и `pTableTail`
(@0x301803CC). До маркера — 17 реальных записей + пустые слоты.

**NAND = ровно 256 МБ**: `cdromiso` заканчивается на 0x05200000 + 0x0AE00000 =
**0x10000000 = 256 МБ** — подтверждено из образа (совпадает с [web: balong_series]).

Примечания: `Logo` и `/yaffs3…6` имеют size 0 при ненулевом type — вероятно,
создаются/расширяются динамически или их контент входит в соседний раздел [гип];
`/yaffs0` и `Logo` share offset (Logo пустой). Коды типов сверены с `balongflash/ptable.c`
(набор `_R1`) — для 0x106/0x108/0x10C/0x10D/0x10E/0x110/0x111/0x112 имена в balongflash
отсутствуют, здесь они выведены из имён разделов/контекста [гип].

## 3. Закрытые открытые вопросы

1. **docs/06 §8.1 (имена разделов)** — закрыто: полный список выше.
2. **docs/10 §5.8 (A/B у USBL)** — закрыто: **BootLoad существует в одном экземпляре**,
   A/B‑пары нет (в отличие от BootRom, у которого копий две). ⇒ перепрошивать BootLoad
   можно только при подтверждённом bootrom‑канале восстановления (тестпоинт);
   штатный DLOAD в BootLoad не пишет (он сам загрузчик) [гип: роль в конвейере].
3. **docs/10 §1.6/§5.3 (эталон 0x2ffffffc)** — закрыто: `DAT_3000511C` = **0x98765432**.
   Если слово персистентной SRAM @0x2ffffffc ≠ 0x98765432 при старте → `nand_erase_all()`.
4. **docs/08 §6 (объём NAND)** — закрыто: **256 МБ** подтверждены геометрией таблицы.

## 4. Новые факты для порта Linux (дополнение к docs/08/09)

- **Ядро Linux**: раздел `kernel` @flash **0x03300000**, лимит **3 МБ**, type 0x105.
  Формат содержимого: сырой образ ядра (как у balongflash‑разделов) [гип — уточнить
  по дампу штатного раздела];Balong‑семейство перед ядром может иметь 128‑байтный
  ptable‑заголовок [web: balong‑kernel README, для V7R11].
- **VxWorks‑модем**: 32 МБ @0x6A0000 — неизменен; IPC с Linux как в штатной архитектуре.
- **rootfs**: `/yaffs1` (28 МБ, System_R1) — если port кладёт rootfs на NAND; либо
  initramfs в ядре (RAM‑бюджет ~15 МБ свободных под штатным Linux).
- **GPIO IRQ**: 6 банков → **IRQ 112–117 (0x70–0x75)** — таблица @0x301808C0
  (DAT_300357bc → intConnect по банкам).
- **Таймер sysClk**: опорная частота **19.2 МГц** (0x0124F800, DAT_30009584);
  конфигурации в BSS (0x3017D4AC–0x3017D510) — заполняются рантаймом.
- **NAND‑контроллеры**: в коде инициализируются **nandc2/nandc3/nandc4** (маски адресных
  циклов 0x1FF/0x555/0x7FF), magic 0x19840815 в `nand_init_platform`; таймауты 10 000 /
  100 000 (мс/тики). База MMIO по‑прежнему в BSS/конфиге — открытый пункт (docs/06 §8).
- **USB burn‑профиль**: u16‑поток @0x301815B0 подтверждает: DevIdx=0, FdCount=3,
  **DevPid=0x1C05**, OSType‑маска 0x00808080, fdTypes = 6,6,1,6,2,6 (MODEM,MODEM,DIAG,
  MODEM,PCUI,MODEM [гип]).

## 5. Методика

python‑дамп `usbl_payload_30004000.bin` (off = VA − 0x30004000): указатель `*DAT_3002c454`
→ 0x3018000C, проход с шагом 0x30 до маркера `pTableTail`; поля — `struct.unpack('<12I')`
на запись; имена — первые 16 байт до NUL. Типы сверены с кодами `balongflash/ptable.c`
(https://github.com/forth32/balongflash). Дамп‑скрипт: `mine_pt.py` в корне workspace.
