# Проверка upstream API для Linux 4.19

## Область и источник

Эта сводка фиксирует проверку API, нужных для оценки переноса vendor-ядра
Balong Linux `2.6.35.7` на базу Linux `4.19`. Доступный локальный upstream
снимок был shallow bare clone stable-репозитория на теге `v4.19.325`,
peeled commit `a67e7cdde7cc7984ae24c3c81a70dc1aa34424b1`. Полная история не
загружалась повторно. Для границ версий сравнивались снимки релизных тегов;
если известен только интервал между тегами, ниже не приписывается конкретный
коммит удаления или добавления.

Это статическая проверка исходного кода, а не сборка ядра, userspace или
прошивки, и не испытание на модеме. Документы SDK, указанные в передаче
контекста, обновлялись отдельно: `DOCS/03a`, `DOCS/10` и связанная строка в
`DOCS/04`. Эти внешние для данного репозитория файлы здесь не копируются и не
изменяются.

## Проверенные границы и выводы

| API / признак | Проверенное состояние | Значение для переноса |
|---|---|---|
| ARM `.phys_io` и `.io_pg_offst` | Присутствуют в 2.6.36, отсутствуют в 2.6.37. | Удалить старые поля из описания `machine_desc` для нового ядра. |
| ARM `struct sys_timer` / `.timer` | Присутствуют в 3.8; в 3.9 отсутствуют, используется `.init_time`. | Старый интерфейс таймера нельзя переносить буквально. |
| `clk_prepare` и `clk_prepare_enable` | `clk_prepare` доступен к 3.2; `clk_prepare_enable` — к 3.3. | Использовать требуемую последовательность подготовки и включения часов. |
| `d_alloc_root` | Есть в 3.2, отсутствует к 3.4. | Старые вызовы требуют замены на поддерживаемый API целевой версии. |
| `dma_attrs` | Присутствует в 4.7; заголовок отсутствует в 4.8. | Учитывать изменение DMA API при переносе драйвера. |
| `timer_setup` | Отсутствует в 4.14, присутствует в 4.15. | Для 4.19 доступен новый интерфейс инициализации таймеров. |
| `i_rwsem` | Отсутствует в 4.6, присутствует в 4.7. | Проверить код, зависящий от старого имени/представления inode semaphore. |
| `NF_CONNTRACK_IPV6` Kconfig | Опция присутствует в 4.18, отсутствует в 4.19. | Удаление символа не доказывает, что IPv6 conntrack включён автоматически; конфигурацию нужно проверять отдельно. |
| `kmap_local_page` / `kmap_atomic` | `kmap_local_page` отсутствует в 5.10, присутствует в 5.11; `kmap_atomic` всё ещё есть в 4.19. | Для целевой 4.19 не предполагать наличие `kmap_local_page`. |
| `read_folio` / `readpage` | `read_folio` отсутствует в 5.18, присутствует в 5.19; `readpage` остаётся в 4.19. | Для 4.19 использовать соответствующий её поколению интерфейс файловой системы. |
| `do_gettimeofday` | Присутствует в 4.19, отсутствует в 5.0. | API ещё доступен в выбранной базе, но усложнит последующий перенос на более новые ядра. |
| `gic_init` | Присутствует в stable `v4.19.325`. | Символ существует в проверенном снимке; это само по себе не подтверждает совместимость BSP. |
| NAND scan API | `nand_scan`, `nand_scan_ident`, `nand_scan_tail` и `add_mtd_partitions` присутствуют в `v4.19.325`. | Эти функции не впервые появились в upstream 4.19: разделённые scan API уже есть в vendor 2.6.35.7. Проверять нужно сигнатуры и структуры. |
| `clk_enable` | Присутствует в 4.19. | Сохранять корректное разделение prepare/enable и обратный порядок выключения. |
| `get_sb_nodev`, `get_sb_bdev`, `create_proc_entry` | Отсутствуют к 3.10; точная промежуточная версия удаления здесь не установлена. | Не приписывать удаление конкретному релизу без проверки истории; старые вызовы требуют адаптации. |

Границы вида «к версии X» описывают только сравнение проверенных релизных
снимков и не всегда устанавливают точный первый/последний релиз изменения.
Особенно это важно для `get_sb_nodev`, `get_sb_bdev` и `create_proc_entry`.

## Практические оговорки

- Совпадение имени API не гарантирует совпадение сигнатур, структур данных,
  семантики или правил владения ресурсом.
- Наличие `gic_init` или NAND-функции в upstream не делает vendor BSP
  совместимым с 4.19 автоматически.
- Разделённые `nand_scan_ident` / `nand_scan_tail` имеются уже в исходниках
  vendor 2.6.35.7; перенос требует сопоставить конкретные аргументы и структуры,
  а не считать сами функции новыми для upstream 4.19.
- `clk_enable` существует в 4.19, но не заменяет `clk_prepare`; при переносе
  следует сохранять требуемый порядок подготовки, включения и освобождения
  тактового сигнала.
- Наличие Kconfig-символа в историческом снимке не доказывает, что опция
  включена в конкретной конфигурации ядра.
- Ни один пункт этой таблицы не подтверждает успешную сборку ядра или работу
  драйвера на устройстве.
